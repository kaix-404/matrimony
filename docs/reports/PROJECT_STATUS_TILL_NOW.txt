RECENT (Oct 23, 2026):
  Biodata import (member app + API) - a member can upload a biodata (typed or
    exported PDF, or a plain text file) and have the recognised fields proposed
    for the profile form instead of retyping each one. Extraction is a
    deterministic text parser (no OCR/LLM provider is configured) and runs
    server-side, so the client ships no parser; packages/shared/src/biodata-parse.ts
    is pure and unit-tested, and apps/api/src/profile/pdf-text.ts extracts PDF text
    on node:zlib alone (no new API dependency). Same three-step upload shape as
    photos: the API mints a presigned PUT, the client sends bytes straight to
    storage, then posts the object key to POST /profile/biodata/parse. The API
    reads the document itself and accepts only a key under the caller's own
    biodata/ prefix, so it cannot be pointed at another profile's upload or an
    arbitrary URL; the response is a proposal, never a save. Education, profession
    and community are matched against the master lists for a value id; an unmatched
    one is reported as still needed rather than offered as fillable text. The app
    shows each value with its confidence for review and confirm, and the save goes
    through the ordinary PATCH with the same validators.
  Member app (Phase 9) - apps/mobile (@matrimony/mobile) on Expo SDK 57, React
    Native 0.86 and Expo Router with strict TypeScript, consuming @matrimony/shared
    contracts; the typed API client validates bodies and responses with Zod.
    Auth/onboarding: phone OTP, registration, rotating tokens in expo-secure-store
    with transparent refresh on 401, auth gate, profile creation and completeness.
    Discovery: cursor-paginated locked-card feed with temporary filters and sort in
    a bottom sheet (the API now parses nested filter query objects).
    Member previews and payments: locked/unlocked/expired states, Razorpay checkout
    in a WebView with the order key_id, status polling, unlock expiry in matches.
    Setup fee: verified accounts advance to AWAITING_SETUP_FEE, the home feed gates
    until payment, and a dedicated screen shows Rs 15.00 + 18% GST = Rs 17.70.
    Profile: completeness, field editing, photo upload with primary/delete, biodata
    import, and a visibility toggle. Settings: net-worth discover/visible-to
    preferences, sign out, OTP-confirmed account deletion. Notifications: in-app
    list with unread badges and push registration via expo-notifications ->
    POST /devices.
    For You: curated interest picker, shared-interest recommendation cards, a fifth
    tab, and a graceful coming-soon state while FEATURE_AI_RECOMMENDATIONS is off.
    Tests: Jest via the jest-expo preset covers the feed view model and interest
    helpers and joins the root verify gate; CI also bundles the app with
    expo export --platform web so a broken route or import fails early.
  Unlock pre-expiry reminder (section 15 / C3) - a sweep records one notification
    per unlock about two hours before it expires; ContactUnlock.reminderSentAt plus
    a conditional-update claim make it once-only across restarts/redeploys;
    UnlockExpiryReminder reuses the sweeper timer shape; channel is PUSH and the
    row still shows in the in-app list.
  Push delivery over Firebase (section 42, resolves GAP-12's push half) - PushGateway
    seam with an FcmPushGateway on FCM HTTP v1 (service-account RS256 assertion
    swapped for a cached OAuth2 token, on node:crypto; no legacy server key, no
    firebase-admin); DeviceToken model + DevicePlatform enum and a SENDING claim
    status; POST/GET /devices and DELETE /devices/:token; PushDispatchService claims
    PENDING->SENDING conditionally (at-least-once, never twice-per-worker), requeues
    a stale SENDING row, prunes UNREGISTERED tokens, and a 60-second sweeper drains
    the queue; fails closed when unconfigured.
  SMS OTP delivery (MSG91, resolves GAP-12) - SmsGateway seam with a
    Msg91SmsGateway on MSG91's Flow API; requestOtp sends in production and fails
    closed (401) when unconfigured, still echoes dev_code outside production;
    Flow API chosen over MSG91's SendOTP API so the platform keeps OTP state.
  Admin MFA - hand-rolled RFC 6238 TOTP + AES-256-GCM secret at rest, opt-in
    self-service enrollment, challenge-then-session login, shared lockout, audited
    reset.
  Account retention purge (section 21) - deleteAccount set purgeAfter but nothing
    read it; AccountRetentionSweeper now anonymises an account once its retention
    window closes. purgeDue overwrites the mobile with a per-account tombstone
    (purged:<id>, so the real number can register again), clears email, blanks the
    profile PII/demographics, and deletes photos and interests; Payment and
    ContactUnlock records are kept and the User/Profile rows survive anonymised.
    Idempotent: only isAnonymised:false rows past purgeAfter are matched.
  Report moderation queue - GET /admin/reports, GET /admin/reports/:id,
    POST /admin/reports/:id/review behind report:review; terminal resolution
    pairing action with status; SUSPEND suspends the reported account; every
    review audited.
  AI recommendations (backend + For You tab) - curated interests, feature-flagged
